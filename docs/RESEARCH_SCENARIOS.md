# 千界花园研究场景与证据操作手册

更新：2026-11-06。目标是把花园用于真实、可核验的研究流程，而不是让多模型协作替代原始证据。

所有 `/api/*` 接口都保留主分支的调用方鉴权：`Authorization: Bearer <GARDEN_AGENT_TOKEN>` 或 `X-Garden-Agent-Key`。该入站令牌与出站模型密钥不同，不得复用或写进文档。根路径 `/` 的服务发现不需要模型调用。

## 六类场景

| 场景 | 解决的问题 | 主要产物 | 当前实现边界 |
|---|---|---|---|
| `protocol-rescue` | 原始实验协议、表格或来源不完整 | 求援、回执、证据、评审与发布闭环 | 已持久化完整状态机 |
| `assay-comparability` | 不同方法的 Ki／IC50 被直接合并 | 方法矩阵、文档内配对、不可合并边界 | 返回工作计划，复用协议与验证接口 |
| `structure-sequence-control` | 不同构建被误当独立重复 | 构建差异、配体身份、序列对齐 | 返回工作计划，不自动推断构建相同 |
| `law-discovery` | 单段拟合被包装成普适规律 | 参数出生证、留出检验、失效域 | 返回工作计划，合成数据只验证引擎 |
| `proof-budget` | 证明成本被误当数学真理等级 | 证明、验证、费用和失败分账 | 场景返回工作计划；素数证书竞赛已有真实实现，模型证明仍需独立检查 |
| `toe-adjudication` | TOE 术语冲突被宣传式合并 | 参数映射、矛盾预测、判决实验 | 返回工作计划，不以模型投票代替实验 |

`GET /api/research/scenarios` 读取全部定义，`GET ...?id=protocol-rescue` 读取单项。`POST` 非协议场景会明确返回 `status=planned`，不伪报已完成研究。

## 协议求援的真实使用顺序

1. 核对文档 ID、DOI、题名和已知文本范围，避免同年、同作者或相同标准品数值串错文献。
2. `POST /api/research/scenarios`，以 `scenarioId=protocol-rescue` 创建任务。
3. 将状态从 `draft` 改为 `ready`，再通过获授权的公开学术渠道求援。
4. 用 `POST /api/research/protocol-requests/:id/receipts` 登记发送、回复、退信或备注。发送回执只证明发送动作。
5. 用 `.../evidence` 登记来源 URL、定位、逐字引文、覆盖范围和核验状态。
6. 用 `.../review` 做三角色复核。`dryRun:true` 可先检查材料与模型分配，避免不必要的计费。
7. 取得所有目标文档的已核验协议后，才允许将任务标为 `complete`。完成求援不等于取得全文，也不等于独立重复。

## 六篇 CA 文献的当前基线

- 目标文档：6；明确同酯酶方法：1；方法不足：5。
- 完整全文计数：0；完整协议计数：0；独立湿实验计数：0。
- 已有合并求援邮件发送记录；未收到可升级证据的作者回复。
- 同库策划记录、讲座重复值和另一项研究的完整方法段只作为线索或外部方法上下文。
- 2026-11-06 的三模型复核没有升级证据。模型指出需要追溯“更早发表”的原始文献，而不是把外部 stopped-flow 方法嫁接到目标文献。

这些数字来自 `data/protocol-requests/ca-six-2026.json`，不是模型估计。后续更新必须保留时间、来源和原记录，不能覆盖历史评审。

## 三角色分工

| 角色 | 供应商与模型 | 审查范围 |
|---|---|---|
| `assay-specialist` | Kimi 网关 / `kimi-for-coding` | 底物、酶源、仪器、pH、温度、浓度、孵育、Ki 换算、重复 |
| `provenance-auditor` | RelayRouter / `claude-opus-5-5` | 文档身份、历史引用、数据库转录、独立实验边界 |
| `skeptical-reviewer` | RelayRouter / `gpt-5.5` | 过度解释、证据等级错配、跨研究方法嫁接 |

模型输出只追加到 `reviews`。它不进入 `full_text` 或 `protocol` 计数，也不能把 `independentWetExperiment` 改为真。三模型一致仍只是三路文本意见。

## 证据登记的最低要求

- `lead`：论坛、搜索摘要、待追溯线索。
- `metadata`：书目或数据库元数据。
- `abstract`：摘要，不能补写方法。
- `partial_text`：正文片段，必须说明未覆盖范围。
- `full_text`：已取得并核验的完整文本。
- `protocol`：足以复核关键实验条件的协议。

`verified` 表示来源和片段已被实际检查，不表示论文结论为真。只有核验后的全文／协议进入相应计数。`independentWetExperiment=true` 需要单独的原始实验依据，不能由相同数值或数据库转录推出。

## 安全与可复现

- 真实模型调用必须保留供应商、模型、用量、时间和输入材料。
- 外部邮件、论坛发言或求援必须得到用户授权；不得虚构合作、机构权限、实验或作者回复。
- 测试服务使用独立临时存储，结束后停止进程并删除测试状态，不污染真实六篇案例。
- 密钥只放本机 `.env.local`；公开示例使用空值或占位符。
- 研究组件通过 `garden-widgets` 接口读取快照，主仓库不塞入独立组件实现。

## 下一阶段：方法血缘与可验证证据操作系统

在现有协议状态机之上增加：

1. 显式方法字段与“未知”状态，禁止从相似文献补齐目标方法。
2. `DERIVED_FROM` 来源派生边，把转载、历史引用、同库策划与原始实验分开。
3. 方法指纹比较，只输出已证实相同、存在冲突、信息不足，不把相似度当独立性。
4. 可重放的六篇真实案例投影，以及面向作者求援的精确缺口清单。
5. 只读研究组件和可下载审计快照；没有新证据时，结论应保持不升级。
